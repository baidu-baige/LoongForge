# E2R-Calib：通用动作连续性

`run-all` 和 `retarget` 默认开启 `motion_continuity`。相机修正和通用连续性修正都属于 E2R-Calib；保留的 E2R-Original 未修改。

## 使用

在 `tools/ego2dex` 目录下：

```bash
python cli.py run-all \
  --input_dir /data/your_input \
  --output_dir /data/your_new_output \
  --robot_type panda --with_depth --device cuda:0
```

可选参数：

- `--motion_max_velocity 3.0`：关节角速度上限，单位 rad/s；按输出 fps 转换为每帧步长。
- `--motion_position_tolerance 0.005`：每个有效帧末端相对人手目标的位置误差上限，单位米。
- `--no-motion-continuity`：恢复之前的校正版轨迹处理，保留相机修正。

3 rad/s 是用于数据重定向的连续性参数，未宣称符合任何具体硬件的电机、负载或控制安全要求。

## 原理

原逐帧 IK / 避碰修复仍提供候选姿态，但不直接作为最终动画。新模块从整段数据的中点、四分之一点、四分之三点依次尝试初始解；同一个候选分支向前和向后连续追踪整段目标。采样位置由长度决定，不依赖物体种类或人工抓取时间段。

每一步同时优化双臂，保留关节范围和相对于相邻已接受帧的硬速度界限。残差包含三维末端位置、软姿态目标、速度、加速度以及几何间隙。使用 MuJoCo 几何雅可比，避碰过程中不会通过无约束随机跳解绕开连续性界限。

加速度是软优化目标，当前没有硬加速度或 jerk 限制。手指开合沿用原流程，未做物体专用调整。

最终检查整段：

- 有效手部目标的末端误差全部满足容差；
- 关节不越界，相邻帧速度不超过配置；
- 各帧无机器人自身或双臂穿插；
- 相邻帧线性插值中点也无穿插。

中点检查不是连续时间扫掠碰撞证明。以上检查不涉及被抓物体的力学接触。

若候选都不满足条件，写出 `_continuity.json` 和 `_continuity_rejected.npz` 后报错，不把不合格轨迹作为正常视频或训练样本导出。位置跟踪和限速冲突时，不会自动冻结准备动作、删帧或修改物体运动。

保存的 `_ik.npz`、末端误差、渲染视频和 LeRobot state/action 均来自最终轨迹。

## 适用边界与验证

求解器目前支持旋转关节组成的机械臂，实际素材验证使用 Panda 双臂。当前硬验收针对末端位置和机器人几何；姿态为软目标，误差单独报告。没有声称适用于所有机器人或所有素材，也没有自动解决不合适的基座布局。

本次检查包括：

- 单元测试：分支跳变、移动目标跟踪、fps 对速度界限的影响、不可达目标拒绝、雅可比、模型参数恢复。
- 实际 Panda 模型的末端和接触雅可比与数值差分比较。
- 小圆罐素材：标准 retarget / export / demo 路径重新运行，复用已有分割、背景和深度。
- 另一条窄桌素材：连续性数值检查通过，但原有较大的姿态误差仍存在。
- 绿杯素材：默认 3 rad/s 和 5 mm 条件下未找到合格轨迹，正确拒绝；未套用之前的人工准备姿态处理。

执行单元测试：

```bash
# 在安装好运行依赖、工作目录为本工具根目录的容器内
python -m unittest steps.retarget.test_continuity
```
